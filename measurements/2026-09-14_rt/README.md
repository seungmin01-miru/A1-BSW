2. **200 µs 초과 합계**로 보면 짝수 CPU 8/10/12/14 가 **248 / 253 / 271 / 245** 로 거의 같다. 코어 6이 사건을 *더 많이* 겪는 것이 아니라, **같은 횟수의 사건이 코어 6에서만 400 µs 를 넘겨 버킷이 이동한 것**이다(코어 6의 200–400 이 161·112 로 오히려 적은 이유). → 200–400 µs 급 **공통 방아쇠**가 8코어에 있고, 코어 6은 그것을 약 2배(≈0.35 → 0.6–0.83 ms)로 늘리는 **증폭기**다.
3. 짝수/홀수 비대칭: 200 µs 초과가 첫 스레드(짝수 CPU)에 4~5배 몰리고, 50–200 µs 는 형제 스레드(CPU 9·15)에 몰린다 → 사건은 물리 코어 단위로 오고, 두 하이퍼스레드가 그것을 나눠 받는 모양이다(같은 코어 안에서 한쪽이 길게 막히면 다른 쪽은 짧게).
4. 따라서 **코어 6 제외는 대증요법**이다: >400 µs 는 사라지겠지만 200–400 µs 급 공통 사건(코어당 ~250회/8h, 8시간에 750회 이상)은 그대로 남는다. 공통 방아쇠 후보는 1-2 추적에서 본 "패키지 단위 깨어남 지연"과 1-3/9-15 계수의 IPI(CAL 코어당 41회/분 = 8시간 약 2만 회; 200 µs 초과 사건 ~250회/코어와 자릿수는 다르지만 IPI 중 일부만 스톨을 유발하는 그림과 모순되지 않음). 이를 갈라내려면 `idle=poll`/`intel_pstate` 차단 같은 전원관리 실험(1-6 (b))이 필요하다.
