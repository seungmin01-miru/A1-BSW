## 해석: **전력 제한(PL1 35 W) 충돌**
- 이 PC(Neousys 산업용)는 RAPL PL1 = **35 W**(칩 TDP 65 W 보다 낮게 BIOS 설정), PL2 = 78 W.
- C 는 격리 8스레드(물리 4코어)가 최대 터보를 요청한 채 100 % 폴링 → 4코어 × ~9 W ≈ 35 W 로 **PL1 에 걸림** → 하드웨어 전력 제어기가 클럭을 3.5~3.7 GHz 사이에서 계속 조정. 이 조정 자체가 전이(stall)이며, 정지 없이 반복돼 A 보다 훨씬 많은 사건이 생김. 패키지 전력을 격리 코어가 다 써서 하우스키핑 코어(glmark2 의 CPU 쪽)도 느려짐(GPU 60 %).
- B 가 좋았던 이유: `intel_pstate=disable` + acpi-cpufreq 는 터보를 노출하지 않아 **기준 클럭 2.1 GHz 고정** → 4코어 ≈ 15 W, 전력 여유 → 클럭 전이 없음.
- 열 스로틀 카운터는 열 제한만 세므로 전력 제한 조정은 0 으로 보임(오해 주의).

## 해석
- 격리 코어 자신의 클럭·절전은 완벽히 고정됐는데도 사건이 남았고 A 보다 많았다. → **원인은 격리 코어 안에 있지 않다.** B 와 C2 의 차이는 하나뿐: **하우스키핑 코어(0-7,16-19)의 HWP 주파수 전이**가 B 에서는 없고(전역 `intel_pstate=disable`) C2 에서는 그대로 있다.
- 결론: 부하가 걸린 하우스키핑 코어가 클럭을 바꿀 때 **패키지 공용 자원(전압 레일/전력 제어기)이 전이**하고, 그 순간 격리 코어를 포함한 전 코어가 수백 µs 멈춘다. 1-2 추적의 "8코어가 같은 순간 늦게 깸"과 정확히 맞는다. 코어 격리(`isolcpus`)는 이것을 막지 못한다 — 같은 칩 위에 있으니까.
- C2 가 A 보다 나쁜 이유(추정): 격리 코어 8스레드가 2.1 GHz 로 항상 폴링하면서 ~15 W 를 상시 소비 → 하우스키핑 코어가 쓸 수 있는 전력이 줄어 RAPL 이 하우스키핑 클럭을 더 자주 조정 → 패키지 전이가 A 보다 잦음.

## 다음 — C3: 하우스키핑 코어까지 클럭 고정(재부팅 불필요, sysfs)
`intel_pstate/no_turbo=1` + 전 코어 governor=performance + 각 코어 min=max=base_frequency(P코어 2.1 GHz, E코어 자기 base). HWP 를 켠 채로 B 의 "전이 없음" 조건을 만든다. B 에 근접하면 원인 확정(패키지 전이) 및 운용 설정 = "전 코어 기준 클럭 고정". 비용 = 인지 코어도 터보 없음 → 2-1(인지 처리량)으로 감당 여부 판단. localization 위주 경량 인지라면 감당 가능성 높음.

## 해석 — "주파수 전이" 가설도 부족
- 기본 튜닝 부팅의 cpuidle 상태는 원래 **POLL 하나뿐**(`max_cstate=1` 효과) → 모든 A/C/C2/C3 측정에서 코어는 이미 잠들지 않았다. **C-state 는 처음부터 원인이 아니었다.**
- C3 는 전 코어의 요청 클럭까지 고정했는데도 B 와 크게 다르다. B 와 C3 의 남은 차이는 **부팅 시점에만 바꿀 수 있는 두 가지**:
  1. `intel_pstate=disable` → **HWP(하드웨어 자율 전원관리) 자체가 켜지지 않음**. C3 는 HWP 가 켜진 채 요청값만 고정 — 하드웨어(PCU)가 RAPL·전압 관리 등을 여전히 자율 수행할 수 있다. HWP 는 한 번 켜지면 재부팅 전까지 끌 수 없다.
  2. `idle=poll` + `max_cstate=0` → intel_idle 드라이버·cpuidle 프레임워크를 아예 안 씀(유휴 루프 경로가 다름).
- 10초 평균 클럭이 고정돼 보여도 수백 µs 짜리 하드웨어 개입은 평균에 묻힌다(측정 한계).
