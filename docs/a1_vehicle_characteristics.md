## 2. CAN 버스 자체 지연 ★

500 kbps classic CAN, 비트 시간 2 µs. 표준 ID(11 bit) 8 바이트 프레임 = 프레임 108 bit + IFS 3 bit = 111 bit, 비트 스터핑 최악
+24 bit → **135 bit**.

| 항목 | 값 | 계산 |
|---|---|---|
| 프레임 1개 전송 시간 | **0.22 ~ 0.27 ms** | 111 ~ 135 bit × 2 µs |
| 0x210 최악 중재 대기 | **약 1.35 ms** | 전송 중인 프레임 1개(비선점) + 우선순위가 높은 0x156·0x157·0x200·0x201 각 1개 = 5 × 0.27 ms |
| 버스 부하 | 평상 5 %(203 프레임/s), 원격 포함 8.6 %(345), 최대 20 %(재연결 몰림 813) | 10-07 실측 |

→ 버스는 지연 예산에서 무시할 수준(1.4 ms 이하). 실제 병목은 아래 액추에이터.

## 3. 액추에이터 지연·동특성 (10-07 리프트)

| 축 | 무반응(dead time) | 63 % 도달 | 90 % 도달 | 그 밖 |
|---|---|---|---|---|
| 조향(핸들각) | **167 ~ 190 ms** (중앙 174) | 192 ~ 262 ms | 213 ~ 304 ms | 최대 속도 관측 **126 °/s**(포화 가능성), 0 근처 **±1.5° 불감대·히스테리시스**, 큰 계단 이득 약 **1.1** |
| 브레이크 | **56 ~ 112 ms** (중앙 87) | 136 ~ 209 ms | 178 ~ 229 ms (한 번 886) | 위치 = 명령 % ÷ 10, 최대 10.0 = 100 % |
| 가속 | 미측정 | — | — | 10-07 은 0x201 바퀴속도가 내내 0 이라 역산 불가 |

잠정 조향 모델: 무반응 0.175 s + 1차 지연(τ 약 0.03 ~ 0.08 s) + 속도 제한 약 125 °/s + ±1.5° 불감대.

## 4. 종단 지연 예산 (제어기 출력 → 차량이 움직이기 시작)

| 구간 | 최악 | 근거 |
|---|---|---|
| 제어기 발행 → 어댑터 → 공유메모리 → can_guard → 버스 0x210 | ★ SIL 측정 최소 13.6 / 중앙값 23.7 / p99 33.5 / **최대 33.6 ms** (n = 200) | 어댑터 50 Hz + can_guard 20 ms 주기가 겹친 값(이론 최악 약 42 ms). ⚠️ vcan·비격리 — 격리 코어 값은 아래 명령으로 측정 |
| CAN 버스 | 1.4 ms | 2절 |
| 차량 수락(auto 이미 켜진 상태에서 명령 반영) | 0x200 주기 이내(≤ 22 ms) | 1절 |
| 액추에이터 무반응 | 조향 190 ms / 브레이크 112 ms | 3절 |
| **합계(움직임 시작까지)** | **조향 약 0.23 s, 브레이크 약 0.15 s** | 50 km/h 에서 조향 0.23 s ≈ 3.2 m |

제어기 지연 보상(예측 지연 tap)은 조향 약 0.2 s, 브레이크 약 0.13 s 를 기준으로 잡고, 트랙 T6 에서 실측으로 다시 맞춘다.

격리 코어 측정(현장 PC, sudo 필요): `bash tools/track_day/bringup.sh --sil` 후
`python3 tools/track_day/measure_latency.py --channel vcan0 --steps 200 --csv <세션>/latency_rt.csv` → 이 표 갱신.
